# Gavis 产品体验短板审计（10 视角 fan-out 综合）

> 审计方法：派出 10 个独立子代理，每个扮演一种用户需求场景视角，各自真实阅读源文件（带 `文件:行号` 证据）走完整旅程，输出短板清单。本报告为 10 份原始报告的去重、交叉、综合。证据均已交叉验证：多处高致命问题被多个视角独立命中（如「麻将难度假档」被 3 个视角同时点中、「127.0.0.1 拒连」被 2 个视角同时点中、「平台游戏目录错位」被 4 个视角同时点中）。

## 二、跨视角交叉发现的系统性问题（最高价值）

> 这些是「一个根因 × 多视角同时命中」的问题——单视角发现可能是局部 bug，多视角同时命中意味着它是产品级系统性缺陷。

### S1. 平台游戏目录与文档/训练注册表严重错位（4 视角命中）

> **勘误（2026-09-30，修复期核实）**：本节及 B9 基于 10 个子代理报告的
> 「平台只注册 9 款、UNO 不存在」结论是**过时快照**——修复期代码核实
> 发现工作区 `games.py` 的 GAMES 实际已有 **15 款**（含 6 个 UNO 变体
> 与完整的 `_uno_snapshot`/`_uno_run_ai` 装配），且前端已存在
> `UnoTable` 组件与 `FAMILY_BOARDS["uno"]` 条目。真实缺口收窄为：
> **werewolf/undercover 仍不在平台注册表**（仅自定义游戏入口可达）；
> `GameInfo.kind` 类型联合缺 `'uno'`（类型谎言，运行时无碍）；大厅
> 徽标对非棋盘类渲染 `🎯 null×null`。三处已在本轮修复。S1 的根因
> 论断（三处注册点各自维护、缺单一注册源）依然成立。

- **现象（勘误后）**：平台注册表 15 款（月亮棋/随机五子棋/德州/6 麻将/6 UNO），但训练注册表 `train-cli/games.py` 有 17 款（多出 werewolf/undercover），用户文档 `docs/user/` 有 7 篇——卧底/狼人杀仍「文档齐全却扑空」。
- **多视角命中**：新手#4（文档-大厅断链）、社交 B1/M9（旗舰社交游戏零入口）、训练#15（三环覆盖面错位）、复盘#15（标签缺漏）。
- **团队已知未修**：`games.py` 注册表注释表明团队知道「平台/训练/文档三个注册点必须同步」，却只补了麻将与 UNO。
- **根因**：缺乏单一游戏注册源（single source of truth），三处各维护一份。
- **修复**：以 `train-cli/games.py` 为唯一注册源，平台/文档从其派生；补 werewolf/undercover（social 族 `build_spec` 已就绪）。

### S2. 麻将难度体系系统性失信（3 视角命中）

- **现象**：六种麻将三档难度预算全为 `1`，`games.py:607/628/649/670/691/712` 注释自认「难度档仅作展示」，UI 却照常渲染「简单/普通/困难」。
- **多视角命中**：新手#9（隐性欺骗）、硬核#7（Blocker）、麻将#16。
- **叠加**：硬核#8 自适应难度窗口用 tally 合成「wins 全在前」序列，高胜率玩家反被降档（越打越简单）。
- **根因**：难度档是 UI 装饰而非引擎参数；自适应难度读不到真实时序。
- **修复**：启发式加噪声/贪心深度档，或 UI 明示「麻将 AI 强度当前固定」；profile 存逐局时序。

### S3. AI 决策黑盒 + 复盘评估全链失效（2 视角命中，硬核+复盘）

- **现象**：
  - 协议层 `solver_provider.py:22-37` 只返回 action，MCTS 搜索树/Q 值/深度每手即弃（`mcts/solver.py:115-116`）。
  - 后端 `session.py:135` 每步已算 `evaluation` 随快照下发，但前端 `types.ts:39-152` 四个 Snapshot 接口无此字段，`grep evaluation` 在 `platform-frontend/src` 零命中——**数据已在网络上传输却被整体丢弃**。
  - 复盘评估器 `analyzer.py:199-202` 只认 `snapshot["board"]`，扑克/麻将快照无此键 → turning_point 退化为「取首步」；五子棋用黑白棋式 material+角+中心打分≈常数。
  - 关键节点封顶 3 个（`analyzer.py:115`），「胜负手=胜方最后一手」，blunder 只在玩家落败时报告（`analyzer.py:312`，「赢棋无失误」是错误心智模型）。
  - 无分支推演/悔棋（全库 grep `undo|悔棋|takeback|branch` 零命中）。
- **多视角命中**：硬核 5 个 Blocker + 复盘#9 评语覆盖率≤3/无评估曲线。
- **根因**：复盘被设计成「带评语的视频播放器」而非分析工具；评估器是通用启发式而非按家族分派。
- **修复**：①类型层加 `evaluation` 可选字段 + BattlePage 渲染胜率条（半天工作量，离修好最近的 Blocker）；②复盘时用求解器离线重算每手局面，或按 gamespec 家族接不同评估器；③支持从第 N 手 fork 分支推演。

### S4. 单 HTTP 请求同步跑完所有 AI 动作（2 视角命中，麻将+社交）

- **现象**：`families/mahjong.py:150-163` 与 `families/social.py:397-417` 的 `_run_ai` while 循环在**同一个 HTTP 请求里**跑完所有 AI 回合；人类血战胡牌后整局余下过程一次性演完；9 人狼人杀一轮白天=8 次 LLM 调用挤在一个请求里，可能数分钟白屏。
- **多视角命中**：麻将#9（血战胡牌后看不到后续战局展开）、社交 M1（嘴炮节奏为零）。
- **根因**：AI 动作无逐步推送机制（log 其实已存每步快照，但前端不消费）。
- **修复**：AI 动作改为可步进（SSE/轮询分步执行 `on_ai_action`），前端逐条演出 + 可调速/跳过。

### S5. 启动与首访门槛过高（新手为主，移动叠加）

- **现象**：
  - `README.md:18-52` 只有 pip install + 训练 CLI，**没有平台启动命令**；须 `npm install && npm run build`（`server.py:132` 503 提示证实）。
  - dist 未构建时浏览器裸收 503 JSON「前端未构建，请先运行 npm run build」（`server.py:126-134`）。
  - 后端未起时首页静默回退 mock 假数据（假目录/假战绩/「阿远」，`HomePage.tsx:22-27` + `mock.ts:6-22`），点击才报错。
  - 默认落地 ChatPage 而非首页（`App.tsx:18` + `sessionStore.ts:15`），与文档「大厅选择」旅程错位。
- **根因**：面向开发者自测交付，未做「5 分钟开局」的产品化封装。
- **修复**：README 置顶「玩一局」段 + 一键 start 脚本；启动自检 dist 给 HTML 引导页；首页禁用 mock 兜底改为显式「后端未启动」横幅。

### S6. 移动端全链路未适配（移动为主，与观战/隐私同根）

- **现象**：
  - 服务器默认绑 `127.0.0.1`（`server.py:520`），手机物理上打不开 8770——同时是移动#1、观战#1（分享链接不可达）、隐私#3（边界写在文档里）的共同根。
  - 侧栏 210px 固定（`global.css:62-71`），375px 屏内容区仅 93px，平台模式 9 页集体不可用（团队已知 P2-28 未修，`docs/review/project-review.md:193`）。
  - 棋盘全固定像素：月亮棋 3×3=320px、五子棋 9×9=464px，手机可用宽仅 ~303px 全部横向溢出。
  - 无 PWA（无 manifest/图标/SW）。
- **修复**：文档加 `--host 0.0.0.0` 移动指引；≤768px 侧栏转抽屉；棋盘 `width:min(100%, N*var(--cell))` 自适应。

### S7. 无障碍全面缺失（无障碍为主）

- **现象**：
  - 棋盘格子全是 `<div onClick>` 无 role/tabIndex/键盘事件（`MoonBoard.tsx:18-25` 等），键盘落子不可行。
  - 棋子纯色圆 div 无 aria-label，黑白仅靠颜色区分（WCAG 1.1.1/1.4.1 双违反）。
  - 全站零 aria-live/role="status"/role="alert"——回合切换、AI 思考、回复、错误、终局全部静默。
  - 无 prefers-reduced-motion（8 组动画无条件播放含抖动）。
  - 大厅卡片、复盘步骤、麻将牌等一批 div onClick 键盘不可达（团队已知 P2-29 未修）。
- **修复**：格子改 `<button>` + aria-label；全局加 aria-live 与 reduced-motion；补 focus-visible。

### S8. 隐私控制名不副实（隐私为主）

- **现象**：
  - 在线学习**捕获关不掉**：UI 开关只停 apply 不停收集，关掉后 trajectories.jsonl 仍在增长（`session.py:268-272` 无条件 wrap）。
  - 「一键清除个人数据」**清不掉个人数据**：只删 profile.json，matches/trajectories/models 全保留；`history.delete/store.clear/model.clear` 共 4 个方法是**无路由死代码**。
  - CORS 通配+零鉴权（`server.py:80-83`），本机任意网页可跨域读对局史/画像并触发写操作。
  - 轨迹库明文存储**全部隐藏信息**（每手完整 state 含 `_arrays`，德州双方底牌、麻将各家手牌），比用户可见历史更敏感。
- **修复**：`enabled(game_id)` 前置到捕获；删除能力接进 API+UI；默认同源 CORS + 本地 token；轨迹只存 info_key+action。

### S9. 自定义游戏创作者三连崩（创作为主）

- **现象**：
  - **命名系统崩溃**：中文名被 `re.sub(r"[^a-zA-Z0-9_]+","_")` 吞成占位符 `generated_alignment_game`（`rule_family_builder.py:176-182`），确定性 100% 触发；变体模式叫 `moon_chess-2` 与内置卡片同名难区分。
  - **规则黑盒**：先手/执子色被静默丢弃（`rule_parser.py:125-151` 只提取棋盘/连珠/消失/子数），用户写「白棋先手」仍黑先；结果面板不展示实际参数（board_size/win_length）；diff_summary 只比较顶层键名；「规则速览」对自定义游戏是占位假文本。
  - **迭代闭环断裂**：无编辑入口、不能基于自定义游戏二次变体、失败不知往哪改、「再建一个」清空全部输入。
- **修复**：display_name 保留原文仅 id 做 slug；结果面板展示关键 constants 表格 + 可展开 rules JSON；加 `PUT /api/custom/games/{id}`；variant 支持以自定义游戏为 base。

### S10. 训练→对弈→评测闭环断裂（训练为主）

- **现象**：
  - 训练产物**断链**（Blocker）：`models/train/` 下的 `.pt`/`cfr_table.json` 在平台运行时（`train-cli/games.py:113-130` RUNTIME_FACTORY 无 artifact 通道）与 benchmark（`benchmark.py:26-36` SOLVER_OPTIONS 无学习型求解器）中均无加载路径。
  - 裸跑默认 `--game all`（小时级作业），无 checkpoint/resume，指标文件最后才写——一次 Ctrl+C 丢全部已完成管线记录。
  - 在线学习门禁三重失效：apply 同步阻塞 HTTP、阈值不可调且 20 局噪声±0.2 远大于 0.03 容差、gate 硬编码 hybrid 使麻将一点「学习」必失败且错误被前端吞掉。
- **修复**：注册表加 `runtime_artifact` 声明 + SOLVER_OPTIONS 增 trained 条目；增量落盘 + `--resume`；阈值进 config API+UI；gate 对手按游戏 runtime_solvers 数据驱动。

### S11. 分享/观战链路为零（观战为主）

- **现象**：
  - **AI vs AI 观战是空头支票**：PRD 场景 D 承诺「AI vs AI 观战、页面实时显示胜率」（`docs/product/product.md:61,99`），实际 benchmark 是纯后台统计器——不可看直播、不可回放任何一局、结果不可导出、重启全丢。
  - 分享链路为零：无公网可达链接（127.0.0.1+本地 JSON）、无步级深链（URL 只有 matchId）、无截图、无棋谱导出（唯一导出是 TXT 摘要不含着法）。
  - 回放只是「手动查看器」：无播放/暂停/变速/键盘/关键手跳转，看一局 150 手五子棋要点 150 次。
- **修复**：导出自包含对局文件 + 前端本地回放器；`?step=` 步级深链；auto-play + 速度档 + ←/→ 键；benchmark 逐手产出快照 + 观战页。

## 七、整体结论与建议优先级

**核心判断**：Gavis 的工程骨架是扎实的——声明式规则引擎撑起六变种麻将/六变体 UNO、隐藏信息安全有 hidden_guard 双防线、本地优先无遥测、注册表驱动零 per-game 架构。但产品化层面存在**系统性缺口**：

- **地基级正确性缺陷**（麻将红中/seed/血战、社交 turn 泄漏、隐私 CORS/捕获）——小修高收益，应立即修。
- **核心承诺落空**（AI vs AI 观战、训练闭环、平台游戏目录、麻将难度档）——需产品决策与中等工作量。
- **核心交互阻断**（无障碍、移动、AI 决策黑盒、复盘体系）——需系统性投入，但 B15（evaluation 渲染）是离修好最近的低成本高收益点。
- **入口门槛**（启动链路、再来一局断链）——留存杀手，应优先产品化封装。

**建议优先级**：
1. **P0（本周）**：地基级正确性 B1-B7 + evaluation 渲染 B15 + 麻将难度 UI 明示 B11 + README 启动 B25。
2. **P1（本月）**：核心承诺 B8-B10 + 社交核心 B12-B13 + 平台目录补齐 B9 + 隐私删除接线 B24。
3. **P2（季度）**：无障碍三连 B19-B21 + 移动三连 B22-B23 + 复盘体系 B16-B18 + 创作三连 S9 + 训练闭环 B10。
4. **P3（持续）**：横切元问题（mock 兜底、死代码接线、文档同步、单请求马拉松、标签统一、ai_pid）。

**一句话总评**：一个把规则引擎与隐藏信息安全打磨得相当认真、却把「第一次玩的 5 分钟、看 AI 怎么想、认真复盘它、和朋友分享、在手机上玩、用键盘玩、控制自己的数据」这些用户真正在乎的事整体留在了协议层之外的产品——骨架真实可用，但产品化的最后一公里，从安装到隐私到复盘，全是台阶。
