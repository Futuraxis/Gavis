# 麻将人机对弈使用说明

平台前端（`layer4_interface/frontend/platform`）内置六种麻将变体，
对局默认 **4 人**（麻将标准人数；引擎仍保留 2 人显式参数），AI 使用
启发式策略（`MahjongHeuristicAI`，无搜索、每步 <1ms）。训练与评测
（train-cli）同样按 4 人装配。

## 启动

```bash
python -m layer4_interface.frontend.platform.server   # 8770（需先 npm run build）
cd platform-frontend && npm run dev                    # 开发模式 5173
```

在游戏大厅选择"广东麻将（鸡胡）/ 红中麻将 / 血流成河 / 四川麻将（血战到底）/
长沙麻将（258将）/ 台湾麻将（16张）"，设置人数与座位后开始。

## 六种变体

| 变体 | 规则 |
|---|---|
| 广东鸡胡 | 自摸/荣和即和牌，单局结束；番种：鸡胡/平胡/碰碰胡/清一色/混一色/七对/龙七对/十三幺 |
| 红中麻将 | 红中（中）为万能牌，可代任意牌凑搭子；红中刻额外一番 |
| 血流成河 | 108 张无字牌；**缺一门**才能胡；**禁吃**；胡牌后**不退场**继续摸打（同一玩家不可二胡），直到 N-1 家胡过或牌墙摸空；计分跨胡**累加** |
| 四川麻将（血战到底） | 108 张无字牌；**缺一门**才能胡（硬门槛）；**禁吃**；胡牌后**退场**（后续轮次跳过），剩余玩家继续至 N-1 家胡或牌墙摸空；番种：平胡 1/对对胡 2/清一色 4/七对 4/龙七对 8/将对 8 |
| 长沙麻将（258将） | 108 张无字牌；**禁吃**；**小胡必须 2/5/8 为将**；大胡（碰碰胡/清一色/七对/将将胡）乱将豁免；将将胡为全 2/5/8 结构豁免；番制 小胡 1 番 → 10 / 大胡 6 番 → 60 / 番上番 12 番 → 120 |
| 台湾麻将（16张） | 无花简化 136 张；庄 17 张、闲 16 张，**5 副+将**成胡；呖咕呖咕（八对半：7 对+1 刻 17 张）可胡；台数：平胡 2/门清 1/自摸 1/碰碰胡 4/混一色 4/清一色 8 |

番数结算：`pay = 10 × 2^(番数-1)`（鸡胡 1 番、平胡 2 番、碰碰胡 3 番、
七对 4 番、清一色 5 番、混一色 2 番、十三幺 8 番、红中刻 1 番）。长沙
使用独立番值表（小胡 10 / 大胡 60 / 番上番 120）。

计分（付分人数 = 在局人数）：**自摸**其余在局玩家各付一份；**荣和为包铳**
——点炮者独付全部份额，其余玩家不掏钱（2026-09 修复：旧版荣和与自摸
同构，无辜玩家一起扣分）。

## 操作

- **摸牌（自动）**：轮到你时牌墙自动摸进一张——刚摸的牌会金色高亮上浮并带「新」角标，桌面中央显示"你摸到了 X"。摸牌不需要按钮，是回合开始时的自动步骤；你只需在摸牌后打出/暗杠/加杠/自摸。
- **打牌**：点击手牌选中（高亮上浮），再点"打出"；或直接使用操作条。
- **自摸**：摸牌后手牌成和 → 操作条出现"自摸"按钮。
- **暗杠 / 加杠**：手牌四张同牌 → "暗杠"；已有碰牌再持一张 → "加杠"。
- **吃 / 碰 / 杠 / 荣和 / 过**：他人打出后进入响应阶段，操作条按可用操作显示。
  - **吃**：仅下家（首个响应者）可吃，且必须从手牌凑齐顺子的另外两张（不能
    “空吃”——手牌没有那两张时不会出现吃选项）；吃后**直接打出一张牌**（不摸牌）。
  - **碰**：手牌两张同牌即可碰；碰后也**直接打出一张牌**（不摸牌）。
  - **杠**：明杠/暗杠/加杠后从牌墙末尾**补摸一张**再打。

## 已知简化（规则文档化，非 bug）

- 吃牌仅首个响应者，且川麻系（四川/血战/长沙）禁吃；无抢杠、无截胡。
  响应优先级为**标准胡>碰/杠>吃**（2026-09 补齐：此前吃/碰/杠按响应队列
  先到先得，首个响应者可能提前于后位的碰/杠）；判定分三阶段执行——
  `claim_mode`：**win**（全队按座次问胡）→ **meld**（全队问碰/杠）→
  **chi**（仅下家问吃），任何后位的胡都优先于先位的碰/杠/吃，后位的
  碰/杠优先于下家的吃。
- 副露（吃/碰/杠）计入胡牌结构与计番（门清手牌 ∪ 副露牌凑 4 副 + 将；
  2026-09 修复：旧版计番只看暗手，副露碰碰胡只按鸡胡 1 番结算）；七对、
  十三幺、呖咕呖咕仍**必须门清**（有副露不可胡这些牌型）。
- 一杯口/二杯口/三杯口（三个相同顺子）可胡：顺子候选按手牌可供应份数
  入池，供应到牌池上限 4 份（2026-09 补齐：旧模型每顺子至多 2 份，三杯口
  及以上不在模型内；现按 `min_t(手牌张数+癞子数)` 多重供应，四杯口 12 张
  + 将同样可胡）。
- 龙七对（一组四张 + 五对）按"四张作两对"计（七对番只认纯七对，龙七对
  独立番种：四川 8 番，其他变体计 0）。
- 红中万能的覆盖验证为近似（顺子缺口按张数计，可能出现稀有误判）；
  万能牌只在红中变体生效（其余变体红中是普通字牌）。
- 血战/血流计分按胡牌顺序**累计结算**（2026-09 修复：旧版每次胡牌覆写
  payoffs，先前胡家的分数被清零）：每位胡家结算时按包铳/自摸模型付分，
  多家胡牌后分数逐次累加，终局零和；终局快照的 `winners` 列出全部胡家
  （无单一 `winner`）。血流成河胡家**不退场**（对比四川血战到底退场），
  靠 winners 守卫禁止同一玩家二胡。
- 每局从新派生的随机种子发牌（首局固定种子保证回归测试确定性，
  「再来一局」不再摸到同一副牌）。
- 平胡/碰碰胡/混一色/缺一门为近似判定（按手牌结构判断）。
- 四川的刮风下雨（杠结算）、查叫/查花猪不实现；海底捞月（8 番）已实现
  （含 108 张牌型的牌池抽干判定）；杠上花（8 番）番别名已声明但流程
  不可达（杠后手牌 <14 张，不计番）。长沙的海底捞月/杠上开花（各 6 番）
  已实现；血流成河同样有海底捞月（8 番）。
- 长沙的副露合并进将将胡判定为近似（将将胡按整手牌集合判定）；连庄省略。
- 台湾无花（v1 简化）、连庄/拉庄/抢杠/过水/眼牌/听牌宣告省略；
  计分按倍率表近似真实"底+台"模型。
- 评测（benchmark）按注册表人数对局（麻将现为 4 人）：A/B 求解器分派
  前两个座位，其余座位由 B 侧驱动。

## 规则实现

- 全部逻辑在 `rules/mahjong.json`（一套 JSON 通吃六种变体与人数），
  变种/人数由 JSON 的 `variants` 节声明（`variant` + `player_count` +
  `options[n].constants` 补丁），引擎纯数据解析，无 per-game 适配器。
- 修改规则请改 `_gen_mahjong.py` 后运行 `python _gen_mahjong.py` 重新生成。
