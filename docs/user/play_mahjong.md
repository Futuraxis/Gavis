# 麻将人机对弈使用说明

平台前端（`layer4_interface/frontend/platform`）内置六种麻将变体，
支持 **2 人 / 4 人** 对局，AI 使用启发式策略（`MahjongHeuristicAI`，
无搜索、每步 <1ms）。

## 启动

```bash
python -m layer4_interface.frontend.platform.server   # 8770（需先 npm run build）
cd platform-frontend && npm run dev                    # 开发模式 5173
```

在游戏大厅选择"广东麻将（鸡胡）/ 红中麻将 / 血战到底 / 四川麻将（血战到底）/
长沙麻将（258将）/ 台湾麻将（16张）"，设置人数与座位后开始。

## 六种变体

| 变体 | 规则 |
|---|---|
| 广东鸡胡 | 自摸/荣和即和牌，单局结束；番种：鸡胡/平胡/碰碰胡/清一色/混一色/七对/十三幺 |
| 红中麻将 | 红中（中）为万能牌，可代任意牌凑搭子；红中刻额外一番 |
| 血战到底 | 胡牌后不退出，剩余玩家继续，直到两家胡或牌墙摸空 |
| 四川麻将（血战到底） | 108 张无字牌；**缺一门**才能胡（硬门槛）；**禁吃**；胡牌后继续至 N-1 家胡或牌墙摸空；番种：平胡 1/对对胡 2/清一色 4/七对 4/龙七对 8/将对 8 |
| 长沙麻将（258将） | 108 张无字牌；**小胡必须 2/5/8 为将**；大胡（碰碰胡/清一色/七对/将将胡）乱将豁免；将将胡为全 2/5/8 结构豁免；番制 小胡 1 番 → 10 / 大胡 6 番 → 60 / 番上番 12 番 → 120 |
| 台湾麻将（16张） | 无花简化 136 张；庄 17 张、闲 16 张，**5 副+将**成胡；呖咕呖咕（八对半：7 对+1 刻 17 张）可胡；台数：平胡 2/门清 1/自摸 1/碰碰胡 4/混一色 4/清一色 8 |

番数结算：`pay = 10 × 2^(番数-1)`（鸡胡 1 番、平胡 2 番、碰碰胡 3 番、
七对 4 番、清一色 5 番、混一色 2 番、十三幺 8 番、红中刻 1 番）。长沙
使用独立番值表（小胡 10 / 大胡 60 / 番上番 120）。

## 操作

- **打牌**：点击手牌选中（高亮上浮），再点"打出"；或直接使用操作条。
- **自摸**：摸牌后手牌成和 → 操作条出现"自摸"按钮。
- **暗杠 / 加杠**：手牌四张同牌 → "暗杠"；已有碰牌再持一张 → "加杠"。
- **吃 / 碰 / 杠 / 荣和 / 过**：他人打出后进入响应阶段，操作条按可用操作显示。

## 已知简化（规则文档化，非 bug）

- 吃牌仅首个响应者且四川禁吃；无抢杠、无截胡。
- 红中万能的覆盖验证为近似（顺子缺口按张数计，可能出现稀有误判）。
- 血战计分仅结算最后一位胡家（先前胡家的番数不累计）。
- 平胡/碰碰胡/混一色/缺一门为近似判定（按手牌结构判断）。
- 四川的刮风下雨（杠结算）、查叫/查花猪不实现；海底捞月（8 番）已实现；
  杠上花（8 番）番别名已声明但流程不可达（杠后手牌 <14 张，不计番）。
  长沙的海底捞月/杠上开花（各 6 番）已实现。
- 长沙的副露合并进将将胡判定为近似（将将胡按整手牌集合判定）；连庄省略。
- 台湾无花（v1 简化）、连庄/拉庄/抢杠/过水/眼牌/听牌宣告省略；
  计分按倍率表近似真实"底+台"模型。
- 评测（benchmark）仅支持 2 人座次。

## 规则实现

- 全部逻辑在 `rules/mahjong.json`（一套 JSON 通吃六种变体与人数），
  变种/人数由 JSON 的 `variants` 节声明（`variant` + `player_count` +
  `options[n].constants` 补丁），引擎纯数据解析，无 per-game 适配器。
- 修改规则请改 `_gen_mahjong.py` 后运行 `python _gen_mahjong.py` 重新生成。
