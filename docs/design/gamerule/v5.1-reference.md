## 1. 总览

v5.1 的关键特征：**零 BUILTIN、规则自足**。

- `BUILTIN_FUNCTIONS` 注册表（`check_line`、9 个 `poker_*`）已退役，引擎不再内置任何游戏特供逻辑；
- 顶层 `functions` 块从「声明文档」升级为**真实 alias 定义**（`{"params": [...], "expr": {...}}`），
  引擎构造时经 `expr.set_functions(rules["functions"])` 注册，表达式经 `call` 调用；
- 表达式原语只从纯数学操作角度增加（`choose/range/sort/group/distinct/contains/sum/max/min/at/add/sub/mul/div`），
  禁止游戏特供原语；
- **v5.2 variants 声明式**：变种/人数/配比都在单个 JSON 内声明（`variants` 块），
  引擎纯数据解析（`$variant/$player_count/$constants/$players` 上下文补丁），
  不再有 per-game 适配器、也没有 constants 注入 API；未知 variant → `ValueError`。

### 1.1 顶层块一览

| 块 | 必选 | 说明 |
|---|---|---|
| `meta` | ✅ | 元数据（gameId/name、version、description） |
| `players` | ✅ | 玩家列表（字符串或对象两种形式） |
| `constants` | ✅ | 常量表（标量/列表/字典，表达式通过 `$constants.x` 与平铺名引用） |
| `groundState` | ✅ | 基础存储：定长/可变数组 + env 标量环境 |
| `derivedViews` | ✅ | 派生视图：grid / enum / literal 三种推导源 + 字段表达式 |
| `queries` | 可选 | 命名查询：视图 + 过滤器 |
| `actions` | ✅ | 动作模板（合法动作枚举的源头） |
| `effectors` | ✅ | 效果定义（操作序列） |
| `phases` | 可选 | 阶段定义（id + 可用动作列表） |
| `chance` | 可选 | 随机节点（explicit / uniform 概率） |
| `triggers` | 可选 | 事件触发器（配合 effector 的 `emit` / `enqueueEffect`） |
| `visibility` | 可选 | 可见性规则（默认 public，或按视图/字段投影） |
| `terminal` | ✅ | 终局条件列表 |
| `utility` | ✅ | 收益规则列表 |
| `functions` | 可选 | alias 函数定义（v5.1 起为真实定义而非声明） |
| `variants` | 可选 | v5.2 变体声明（`variant` + `player_count` + `options` **dict**：键=变体名，值为 `{"constants": {...}}` 补丁；缺省为单配置） |

> L1 `SchemaValidator` 的 v5 必需顶层集合为
> `{meta, players, groundState, derivedViews, constants, actions, effectors, terminal, utility}`。

## 2. 根对象

```json
{
  "meta": {"gameId": "moon_chess", "version": "5.1.0", "description": "..."},
  "players": ["p_black", "p_white"],
  "constants": { "board_size": 3 },
  "groundState": { "...": { "type": "array", ... }, "env": { "type": "env", "fields": {...} } },
  "derivedViews": { "cell": { "from": {...}, "fields": {...} } },
  "queries": { "empty_cells": { "view": "cell", "filter": {...} } },
  "actions": [ { "id": "place_piece", "phases": ["playing"], "params": {...}, "legal": {...}, "effectRef": "do_place", "canonicalKey": {...} } ],
  "effectors": { "do_place": { "description": "...", "ops": [ {...} ] } },
  "phases": [ { "id": "playing", "actions": ["place_piece"] } ],
  "chance": [ { "id": "deal", "phases": ["deal"], "probability": {...}, "effectMap": {...} } ],
  "visibility": { "default": "public", "rules": [ {...} ] },
  "terminal": [ { "id": "three_in_row", "condition": {...} } ],
  "utility": [ { "player": "p_black", "value": 1, "when": {...} } ],
  "functions": { "rank": { "params": ["card"], "expr": {...} } },
  "variants": {
    "variant": "guangdong",
    "player_count": 4,
    "options": {
      "guangdong":   { "constants": {} },
      "hongzhong":   { "constants": { "wild_tile": "z5" } },
      "blood":       { "constants": { "tile_ids": [...] } },
      "international": { "constants": { "fan_pay": [1, ..., 88] } }
    },
    "trim_players": true,
    "trim_utility": true
  }
}
```

## 3. meta

```json
{"gameId": "texas_holdem", "version": "5.1.0", "description": "..."}
```

- `gameId` 或 `name`：至少一个（L1 校验）。
- `version`：规则语言版本号。`description`：自由文本。

---

## 4. players

两种等价形式（引擎 `_parse_players` 均接受）：

```json
["p_black", "p_white"]
```

```json
[{"id": "p0", "type": "player"}, {"id": "p1", "type": "player"}]
```

- 表达式中经 `$players` 引用（`$players[i].id` 等）。
- 缺省（无此块）时引擎回退为 `["p_black", "p_white"]`。

## 5. constants

任意 JSON 值：标量、列表、字典、嵌套结构。

```json
{
  "board_size": 3,
  "win_length": 3,
  "max_pieces": 3,
  "dirs": [ {"dr": 0, "dc": 1}, {"dr": 1, "dc": -1} ],
  "rank_of": {"s2": 2, "sA": 14}
}
```

引用方式：

1. 表达式节点：`{"var": "$constants.board_size"}` 或 `{"get": ["$constants", "dirs"]}`；
2. **标量常量平铺**：引擎求值上下文会把 int/float/str 常量平铺到顶层，
   因此算术字符串里可直接写裸名：`{"expr": "$cell.y * board_size + $cell.x"}`（`board_size` 即常量）；
3. 算术字符串中的裸名解析顺序：先 `ctx` 直接键，再 `$` 前缀键（`$dirs` 这种 `as` 绑定同样可被裸名命中）。

## 6. groundState — 基础存储

### 6.1 数组字段

```json
{
  "board":       { "type": "array", "length": {"expr": "board_size * board_size"}, "element": "player_id?" },
  "pieceOrder":  { "type": "array", "mutable": true, "element": {"cell_id": "string", "player_id": "string"} }
}
```

| 键 | 含义 |
|---|---|
| `type` | 固定 `"array"` |
| `length` | 定长数组的长度：`{"const": N}` 或 `{"expr": "board_size * board_size"}`（初始化时求值，只认常量） |
| `mutable` | `true` → 初始为空列表（`[]`），可 `append`/`remove` 动态增长；省略/`false` → 初始 `[None] * length` |
| `element` | 元素类型标注（**声明性元数据**；运行时数组就是 Python list，引擎不强制类型） |

### 6.2 env 字段

```json
"env": {
  "type": "env",
  "fields": {
    "turn":   {"type": "player_id", "initial": "p_black"},
    "round":  {"type": "int",       "initial": 0},
    "phase":  {"type": "string",    "initial": "playing"},
    "winner": {"type": "player_id?", "initial": null}
  }
}
```

- `initial`：初始值（null 表示缺省）。
- env 未声明 `phase`/`winner` 时引擎补默认：`phase="playing"`、`winner=None`。

### 6.3 TypeRef（声明性类型标注）

`"string" | "int" | "float" | "bool" | "player_id"` 及其可空后缀 `"?"`，
或记录型 `{"cell_id": "string", "player_id": "string"}`。仅元数据，运行时不做类型检查。

> 注意：v5.0 文档中的顶层 `initialState` 在 v5.1 引擎中**不读取**；初始化完全由
> `groundState`（数组长度/可变性 + env 字段 `initial`）决定。

## 7. derivedViews — 派生视图

派生视图是「虚拟表」：由基础数组按推导规则（grid / enum / literal）计算实体列表，字段是纯表达式。
视图是状态的纯函数，任何数组/env 变更都会使引擎失效视图缓存。

```json
"derivedViews": {
  "cell": {
    "from": {"type": "grid", "array": "board", "cols": {"const": 3}},
    "fields": {
      "id":       {"template": "cell_{$row}_{$col}"},
      "occupant": {"get": ["$self", "value"]},
      "x":        {"var": "$col"},
      "y":        {"var": "$row"}
    }
  }
}
```

### 7.1 推导源 `from`

| 类型 | 形状 | 实体内置字段 |
|---|---|---|
| `grid` | `{"type": "grid", "array": <name>, "cols": <expr>}` | `value`（数组元素）、`_index`（一维下标）、`_row`、`_col` |
| `enum` | `{"type": "enum", "array": <name>}` | `value`、`_index`、`_i` |
| `literal` | `{"type": "literal", "list": <list 或 {"var": ...}>}` | `value`、`_index`、`_i` |

- `grid`：行主序 `row = index // cols`、`col = index % cols`；`cols` 表达式在
  `{$constants, env, $players}` 上下文中求值。
- `literal` 的 `list` 可以是字面数组，也可以是 `{"var": "$players"}` / `{"var": "card_ids"}` 等
  引用常量或玩家列表（werewolf 的 `player` 视图即 `{"var": "player_ids"}`）。

### 7.2 字段表达式上下文

字段节点求值时的上下文：`$self`（当前实体）、`$row`、`$col`、`$i`、`$env`、`$constants`、`$players`，
外加 `functions` alias（字段里可直接 `call`）。

### 7.3 视图实体引用

- `$self.value`：基础数组元素原始值（grid 的格值、literal 的列表项）；
- moon_chess 的 `occupant` 即 `{"get": ["$self", "value"]}`；
- texas_holdem 的 `card` 视图 `{"var": "$self.value"}` = 牌 id（`"sA"` 等）。

## 8. queries — 命名查询

```json
"queries": {
  "empty_cells": {
    "view": "cell",
    "filter": {"eq": [{"get": ["$node", "occupant"]}, {"const": null}]}
  }
}
```

- `view`：视图名；`filter`：过滤表达式，实体上下文中 `$node` 与 `$self` 均指向当前实体。
- 省略 `filter` → 返回视图全部实体。
- 引用方式：参数域 `{"domain": {"ref": "query_name"}}`；表达式内也可用 `query` 节点。

## 9. actions — 动作模板

```json
{
  "id": "place_piece",
  "type": "move",
  "phases": ["playing"],
  "actor": {"var": "$env.turn"},
  "params": {
    "cell": {"view": "cell", "domain": {"ref": "empty_cells"}}
  },
  "legal": {"const": true},
  "effectRef": "do_place_and_check",
  "canonicalKey": {"template": "place:{$cell.x},{$cell.y}"}
}
```

| 键 | 必选 | 语义 |
|---|---|---|
| `id` | ✅ | 模板唯一 ID（L1 校验重复） |
| `type` | 可选 | 元数据（`"move"`/`"speech"`/`"vote"`/`"night"`/...），落入 `ActionInstance.type` |
| `phases` | ✅ | 该模板生效的阶段列表；引擎只展开当前 `env.phase` 命中的模板 |
| `actor` | 可选 | 行动者表达式，缺省 `{"var": "$env.turn"}` |
| `params` | 可选 | 参数定义（见 §9.1） |
| `legal` | 可选 | 合法性条件，缺省 `{"const": true}` |
| `effectRef` | ✅ | 命中的 effector 名（L1 校验引用存在） |
| `canonicalKey` | 可选 | 规范动作 key，缺省 `{"template": tmpl["id"]}` |

### 9.1 ParamDef

```json
"params": {
  "cell":  {"view": "cell", "domain": {"ref": "empty_cells"}, "filter": {...}},
  "text":  {"type": "text"}
}
```

| 键 | 语义 |
|---|---|
| `view` | 元数据/提示（前端渲染用）；引擎枚举只用 `domain` |
| `domain` | 候选域，四种形式（见下） |
| `filter` | 可选：在 domain 之上对每个候选额外过滤（上下文：`$<参数名>` 与 `$node` 绑定候选） |
| `type: "text"` | **自由文本参数（预制能力）**：不参与合法动作枚举，展开为占位 `""`；求解器把文本写入 `ActionInstance.params`，effector 经 `$text` 读取（`_build_context` 自动平铺 params）。狼人杀 `speak` 的 `text` 参数即此用法 |

`domain` 的四种形式：

| 形式 | 示例 | 语义 |
|---|---|---|
| 字面列表 | `["fold","call","raise"]` 或 `[0,2,4,...]` | 直接枚举（德州扑克 `act` 的 choice/amount 即此） |
| 查询引用 | `{"ref": "empty_cells"}` | 解析命名查询的实体列表 |
| 动态数组 | `{"array": "hand_p0"}`（或表达式 `{"array": {"template": "hand_{$env.turn}"}}`） | 读 ground array 当前内容 |
| 任意表达式 | `{"expr": {...}}` | 求值；非列表结果包装为单元素列表，`None` → 空 |

### 9.2 合法动作展开流程

1. 取当前 `env.phase` 命中的模板（`phases` 过滤）；
2. 对每个参数求候选域；`text` 参数域为 `[""]`；
3. 各参数域取**笛卡尔积**（守卫：组合总数 > 65536 抛 `ValueError`，防组合爆炸）；
4. 每个组合上下文中绑定 `$<参数名>` 与 `<参数名>`，求值 `legal`，不合法丢弃；
5. 求值 `canonicalKey`，构造 `ActionInstance`。

## 10. effectors — 效果操作

```json
"effectors": {
  "do_place": {
    "description": "Place piece + record cell order",
    "ops": [ {"op": "setIndex", "array": "board", "at": {...}, "value": {...}}, ... ]
  }
}
```

每条 op 执行后引擎都会失效视图缓存；所有数组变更保证**克隆隔离**（见 §19）。

### 10.1 数组操作

| op | 形状 | 语义 |
|---|---|---|
| `setIndex` | `{"op":"setIndex","array":A,"at":E,"value":E}` | `groundArray[at] = value`（越界忽略）。`A` 可为名字或表达式 `{"template": "hand_{$env.turn}"}` |
| `append` | `{"op":"append","array":A,"value":E\|值字典}` | 数组尾部追加。`value` 可以是表达式，也可以是"值字典"（每个字段一个表达式，如 `{"cell_id": {...}, "player_id": {...}}`）。注意：对 **env 列表**（数组名不在 groundState、而是 env 里的列表字段），一律**重绑新列表**，绝不原地改（克隆共享陷阱） |
| `remove` | `{"op":"remove","array":A,"value":E,"count":E}` | **多重集差 A⊖B**：按值移除至多 `count` 个匹配项（缺省 1）；env 列表同样重绑 |
| `setArray` | `{"op":"setArray","array":A,"value":E}` | 整体替换数组（env 列表必须整体重绑——克隆共享陷阱）；新列表通过 `list(value)` 保证新鲜 |
| `trimByKey` | `{"op":"trimByKey","array":A,"max":E,"key":K,"value":E,"onEvict":[ops]}` | 按 `key==value` 分组，组内超过 `max` 时**从最旧（队首）开始淘汰**；被淘汰元素执行 `onEvict` 子操作（上下文含 `$evicted` 与 `evicted_index`）。月亮棋 FIFO 驱逐即用此 op |

### 10.2 环境操作

| op | 形状 | 语义 |
|---|---|---|
| `setEnv` | `{"op":"setEnv","key":K,"value":E}` | `env[K] = value` |
| `inc` | `{"op":"inc","key":K,"by":E}` | `env[K] += by`（缺省 +1；非数值当前值按 0 处理） |

### 10.3 控制流

| op | 形状 | 语义 |
|---|---|---|
| `branch` | `{"op":"branch","if":E,"then":[ops],"else":[ops]}` | 条件分支；`then` 缺省视为空分支 |
| `callEffect` | `{"op":"callEffect","effectRef":N,"args":{K:E}}` | 调用子 effector；`args` 各值在**调用方上下文**中求值后并入子上下文 |
| `forEach` | `{"op":"forEach","list":E,"as":"$item","do":[ops]}` | 遍历列表逐项执行 `do`；非列表 → 空迭代；`as` 缺省 `"$item"` |

### 10.4 事件

| op | 形状 | 语义 |
|---|---|---|
| `emit` | `{"op":"emit","event":N,"payload":{K:E}}` | 入队事件 `(event, payload)`，交给触发器（§13） |
| `enqueueEffect` | `{"op":"enqueueEffect","effectRef":N,"args":{K:E}}` | 入队延迟 effect 调用（同样交给触发器循环） |

> `emit` / `enqueueEffect` 目前仅在 `triggers` 机制里消费；已发布的七个规则 JSON（`rules/` 下 moon_chess/stochastic_gomoku/texas_holdem/mahjong/werewolf/undercover/uno）中 triggers 属引擎预留能力。

## 11. phases — 阶段

```json
"phases": [
  {"id": "playing", "actions": ["place_piece"], "description": "..."}
]
```

- `id` + `actions`（本阶段可用的动作模板 id 列表）是引擎实际读取的键。
- 阶段转换**不由 phases 块驱动**：由 effector 里 `setEnv phase` 完成（`{"op":"setEnv","key":"phase","value":{"const":"next_phase"}}`）。
- v5.0 文档中的 `onEnter` / `onExit` / `next` 在 v5.1 引擎中**未实现**，不要依赖。
- 节点类型判定（`get_node_type`）优先级：终局 > chance > 玩家动作：
  1. 任一 `terminal` 条件为真 → `terminal`；
  2. `env.phase` 命中某个 chance 模板的 `phases` → `chance`；
  3. 否则按 phases 定义的 `actions` 是否非空 → `player` / `terminal`。
  即：**同一阶段同时挂 actions 与 chance 时按 chance 处理**。

## 12. chance — 随机节点

```json
{
  "id": "deal_sb1",
  "phases": ["deal_sb1"],
  "params": {"card": {"view": "card", "domain": {"ref": "undrawn_cards"}}},
  "probability": {"uniform": {"over": "card"}},
  "effectRef": "do_deal_sb1",
  "canonicalKey": {"template": "deal:{outcome}"}
}
```

```json
{
  "id": "night_end",
  "phases": ["night_end"],
  "probability": {
    "explicit": [{"outcome": "resolve", "prob": 1.0}]
  },
  "effectMap": {"resolve": "do_night_end"},
  "canonicalKey": {"template": "night:{outcome}"}
}
```

### 12.1 probability

| 形式 | 语义 |
|---|---|
| `{"explicit": [{"outcome": V, "prob": P}]}` | 结果表直接声明概率。`P` 可以是数字或表达式（表达式在普通环境上下文求值）；缺 outcome/prob 的坏条目**优雅跳过** |
| `{"uniform": {"over": P}}` | 以 `params[P]` 的候选域为结果集，每项等概率 `1/n`；结果 key：字典候选取 `id`（否则 `str(c)`） |

- 引擎采样按概率**总和归一化**；结果表为空或全零 → `ValueError`（规则 bug）。
- outcome 的 `effectRef` 解析：`explicit` → `effectMap[outcome]`，缺省 `"do_{outcome}"`；
  `uniform` → `effectMap[cid]`，缺省模板的 `effectRef`（可为空串）。
- 执行时 `ctx["outcome"]` 绑定当前结果 key，effector 里可用 `{"var": "outcome"}` 读取（werewolf `do_deal_*` 即用 `outcome` 追加角色）。
- `canonicalKey` 缺省 `{"template": "chance:{outcome}"}`。

## 13. triggers — 事件触发器（预留）

```json
"triggers": [
  {
    "event": "game_event",
    "condition": {...},
    "effectRef": "do_on_event"
  }
]
```

- `emit` / `enqueueEffect` 入队的 (event, payload) 与 (effectRef, args) 在每次状态变更后被循环排空；
- 触发器执行上下文含 `$event`（payload），payload 键同时平铺进上下文；
- 循环上限 16 轮，防失控级联（超限丢弃余量）。

## 14. visibility — 可见性

```json
"visibility": {
  "default": "public",
  "rules": [
    {
      "view": "sb_hole_view",
      "filter": {"eq": [{"var": "$viewer"}, "p_bb"]},
      "fields": {"id": "hidden"}
    }
  ]
}
```

- `default`：`"public"`（完美信息：观测包含视图全部字段）或其它值（部分信息：按规则逐实体投影）；
- `rules[]`：`view` + `filter`（适用条件，上下文含 `$viewer` 与 `$node`）+ `fields`（字段 → 级别）。
- 引擎视角只有两档：`"public"` = 保留；**任何非 public 值**（`"private"`/`"hidden"`/`"masked"`）= 剔除该字段；
  若某实体有任一字段被隐藏，其原始数组值 `value` 一并剔除（防对手牌 id 泄漏）；
- `env` 字段投影（v5.2）：`visibility.env` 列出的字段按 viewer 条件过滤，未列出的
  env 字段一律全量透传（例：werewolf 的 `seerResult` 仅预言家可见，`round`/`turn`
  等人人可见）；
- `"drop": true`（v5.2）：filter 为假时**整行移除**而非仅隐藏字段（例：`my_role`
  只留 viewer 自己的行；`dead_roles` 用 `alive[_index]==0` 保留死者行——注意是
  "保留死者"，别写成 `alive==1` 导致语义反转）。

## 17. functions — alias 函数（v5.1 核心）

```json
"functions": {
  "rank": {
    "description": "Numeric rank of a card id (2..14)",
    "params": ["card"],
    "expr": {"at": [{"var": "$constants.rank_of"}, {"var": "$card"}]}
  },
  "hand_ranks": {
    "params": ["hand"],
    "expr": {"sort": {"list": {"map": {"list": {"var": "$hand"}, "expr": {"call": ["rank", {"var": "$node"}]}}}, "reverse": true}}
  }
}
```

调用：`{"call": ["fn_name", arg1, arg2, ...]}`。

语义与限制：

- **按名绑定**：调用时实参按 `params` 顺序绑定，函数体内 `$p` 与 `p` 均可引用；
- **禁递归**：构造时静态 DFS 环检测；环上成员一旦被调用抛 `RecursionError`；
- **深度上限**：解释器路径 `_MAX_CALL_DEPTH = 32`；编译路径把 alias 体内联成闭包；
- 实参个数必须等于 `params` 长度，否则 `ValueError`；
- 未知函数调用抛 `ValueError("Unknown function: ...")`；
- `register_function`（注册 Python 可调用对象）是**预留 API**，v5.1 引擎不使用；
- alias 在视图字段、查询过滤器、terminal/utility 表达式中均可调用（共享求值器）。

## 18. 表达式系统（完整节点参考）

表达式节点 = 恰好含一个识别键的 JSON 对象；非 dict 值原样作为字面量。
求值入口：`expr.eval(node, ctx)`；热路径（const/var/get/template/switch/比较/逻辑/if）编译为闭包，
语义与解释器一致（单测强制双路径一致性）。

### 18.1 字面量与路径

| 节点 | 示例 | 语义 |
|---|---|---|
| `const` | `{"const": 3}` / `{"const": null}` | 原样返回 |
| `var` | `{"var": "$env.turn"}` / `{"var": "board_size"}` | 按点分路径解析；`$` 前缀可省略；每层先取裸键再取 `$` 前缀键；**列表段索引越界/负索引 → None**（边界安全） |
| `get` | `{"get": ["$node", "id"]}` / `{"get": [{"var": ...}, "field"]}` | 与 `var` 同一条路径解析器；`get` 的**第二参数只能是字面量**（字段名/索引），动态索引必须用 `at` |

### 18.2 字符串

| 节点 | 示例 | 语义 |
|---|---|---|
| `template` | `{"template": "cell_{$row}_{$col}"}` | 插值 `{expr}`（expr 为路径）；缺失值 → 空串 |
| `concat` | `{"concat": [A, B]}` | 全部为列表 → **摊平拼接**；否则按字符串拼接；`None` 项一律丢弃（部分组合不污染结果） |

### 18.3 算术简写 `expr`（标量字符串）

```json
{"expr": "$cell.y * board_size + $cell.x"}
{"expr": "$env.lastPlacedIndex // board_size + (j - k) * d.dr"}
```

- 支持 `+ - * / // % **` 与括号、变量替换；
- `$` 前缀变量与裸名（常量平铺名、`as` 绑定名如 `d`/`j`/`k`）均可代入；
- **仅支持标量**：列表/字典值无法代入（非数值替换为 0）；组合型算术用 `add/sub/mul/div` 节点；
- 求值失败返回 `None`。

### 18.4 算术节点（对节点结果做算术）

| 节点 | 语义 |
|---|---|
| `add` / `sub` / `mul` | `{"add": [a, b]}`；两操作数先求值再运算 |
| `div` | 整数整除 `int(a) // int(b)`；非法操作数/除零 → `None` |

### 18.5 条件分支

| 节点 | 示例 | 语义 |
|---|---|---|
| `if` | `{"if": <cond>, "then": ..., "else": ...}` 或 `{"if": {"cond": ..., "then": ..., "else": ...}}` | `then` 缺省 `true`，`else` 缺省 `None` |
| `switch` | `{"switch": [{"case": "p_black", "then": "p_white"}, {"case": "p_white", "then": "p_black"}], "input": {"var": "$env.turn"}}` | 顺序匹配 `case == input`；无 `case` 键的条目为 default（可多个，取首个）；无命中 → `None`；`input` 缺省 `{"var": "$input"}` |

### 18.6 比较与逻辑

| 节点 | 语义 |
|---|---|
| `eq` / `neq` / `gt` / `gte` / `lt` / `lte` | `{"eq": [a, b]}` 等 |
| `and` / `or` | `{"and": [e1, e2, ...]}`（短路） |
| `not` | `{"not": e}` |

### 18.7 集合操作

| 节点 | 形状 | 语义 |
|---|---|---|
| `filter` | `{"filter": {"list": L, "as": "$node", "where": E}}` | 保留 `where` 为真的元素；非列表 → `[]` |
| `any` | `{"any": {"list": L, "as": "$node", "where": E}}` | 任一成立；非列表 → `false` |
| `all` | `{"all": {"list": L, "as": "$node", "where": E}}` | 全部成立；非列表 → `true` |
| `map` | `{"map": {"list": L, "as": "$node", "expr": E}}` | 逐元素映射 |
| `count` | `{"count": X}` | 列表/字典长度，否则 0 |
| `distinct` | `{"distinct": X}` | 去重（保持首次出现序；不可哈希项线性扫描兜底） |
| `contains` | `{"contains": [容器, 元素]}` | 容器非列表 → `false` |

`as` 缺省 `"$node"`；`sort`/`group` 的 `by` 里同时绑定 `$node` 与 `$item`。

### 18.8 聚合

| 节点 | 语义 |
|---|---|
| `sum` | 列表求和；非列表 → 0；空列表 → 0 |
| `max` / `min` | 列表最值；非列表或空 → `None`；元素不可比 → `None` |

### 18.9 序列 / 排序 / 分组

| 节点 | 形状 | 语义 |
|---|---|---|
| `range` | `{"range": {"from": a, "to": b, "step": s}}` | Python 语义 `[from, to)`；`from` 缺省 0，`step` 缺省 1；`step=0` → `[]` |
| `sort` | `{"sort": {"list": L, "by": E, "reverse": bool}}` | 无 `by` 直接排序；有 `by` 按键排序（`by` 上下文含 `$node`/`$item`）；不可比 → 保持原序 |
| `group` | `{"group": {"list": L, "by": E}}` | 按键分组（`by` 缺省按元素自身）；返回 `[{"key": K, "count": n, "items": [...]}]`，**首次出现键序** |

### 18.10 组合 `choose`（v5.1 新增）

```json
{"choose": {"items": L, "k": n, "as": "$c", "prefix": P, "where": W, "then": T, "agg": "max"}}
```

- 输入先**按值排序去重**（C(unique, k)），`k` 夹紧到 `[0, len(uniq)]`；
- `prefix`：前缀剪枝（**单调契约**：部分组合失败 ⇒ 一切扩展失败；只门控更深搜索，完整组合由 `where` 判定）；
- `where`：过滤完整组合；`then` + `agg`（`"max"|"min"`，缺省 max）返回满足组合的最优 `then` 值；
- 无 `then` 时返回「是否存在满足组合」的布尔；
- 组合上下文：`as` 变量（缺省 `$c`）与 `$node` 均绑定组合列表。
- 用途：德州扑克 `best5`（从 7 张里 C(7,5) 枚举最佳 5 张）。

### 18.11 动态索引 `at`（v5.1 新增）

```json
{"at": [容器, 索引表达式]}
```

- 容器为 dict → `dict.get(idx)`；list/str + 非负整数索引 → 元素；
- **负索引与越界一律 `None`**（"自然过滤"契约：棋盘胜负判定的滑动窗口读数组边缘即得 None，
  严禁索引回绕——见 `test_expr_eval.py::TestWinCheckShape`）。

### 18.12 查询节点

```json
{"query": {"view": "cell", "filter": {...}}}
```

- 依赖上下文的 `_query_fn`（引擎注入）；无则返回 `[]`；
- `filter`/`where` 二键皆可，实体上下文绑定 `$node`/`$self`；
- 用途：terminal/utility/count 里的行内查询（werewolf `alive_wolves` 等）。

### 18.13 函数调用

```json
{"call": ["rank", {"var": "$node"}]}
```

见 §17 的 alias 调用规则。

## 19. 求值上下文（context）

引擎 `_build_context` 组装，表达式可引用：

| 变量 | 内容 |
|---|---|
| `$state` | 完整状态 dict |
| `$env` | env 标量环境（`$env.turn`、`$env.phase` 等） |
| `$constants` | 常量表整体 |
| `$players` | 玩家列表（字符串或对象形式） |
| 常量平铺 | 每个 int/float/str 常量以裸名出现在顶层（`board_size`） |
| `$<数组名>` | 每个 ground array 以 `$` 前缀键出现（`$board`、`$hand_p0`） |
| `$action` | 动作实例（apply_action 时） |
| `$params` | 动作参数字典（apply_action 时） |
| `<参数名>` / `$<参数名>` | 每个动作参数双键绑定（`$cell`、`cell`；text 参数即 `$text`） |
| `outcome` | chance 结果 key（apply_chance 时） |

| `$viewer` | 观测投影目标玩家（visibility 规则里） |

## 20. 状态表示与克隆语义

内部状态结构：

```python
{
    "_arrays": {...},  # ground arrays
    "_schema": {...},  # 只读
    "_players": [...],
    "_constants": {...},
    "env": {...},  # 标量环境
    "_pending_events": [],  # emit 队列
    "_pending_effects": [],  # enqueueEffect 队列
    "_view_cache": {...},  # 视图缓存（变更即失效）
}
```

- `clone_state` 浅拷贝：数组逐项 `list()` 拷贝、env 浅拷贝——**env 里的列表是引用共享**，
  所以 `append`/`remove`/`setArray` 对 env 列表一律**重绑新列表**（克隆隔离契约，见 engine `_execute_op` 注释）；
- 视图是 (arrays, env, players, constants) 的纯函数并缓存于 `_view_cache`，任何 op 变更即失效；
- `load_state`：外部状态导入（VLM 等），缺失的数组/env 用 schema 默认补齐。

## 21. 判定原则（增量局部 O(1)）

所有胜负/轮结束判定围绕上下文字段做局部计算，**禁止全局穷举**：

- 五子棋/月亮棋连子：围绕 `lastPlacedIndex`（`env.lastPlacedCell` 的索引）的四方向滑动窗口，
  方向用 `constants.dirs`（`{dr, dc}` 表）表达，行/列守卫保证斜线不跨行错连；
- 麻将和牌：围绕手牌 + `lastDiscard`/`lastDrawn` 的覆盖验证（`Σ min(sel_g, have_g) + wild ≥ 14`）；
- 德州扑克下注轮结束：`env` 的 committed/acted 字段。
