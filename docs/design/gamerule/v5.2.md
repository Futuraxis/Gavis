# 通用游戏规则语言 v5.2（现行）

> 版本: v5.2 | 状态: **现行**（取代 v5.1/v5.0/v4.1，后三者见各自文件「已取代」横幅）
> 日期: 2026-08（与代码现状对齐）
>
> v5.2 在 v5.1「零 BUILTIN + 纯函数 alias」基础上补上两块声明式能力：
> **`variants` 声明式**（变种/人数/配比/常量补丁全部在单个 JSON 内声明，
> 引擎纯数据解析，无任何注入 API）与 **`visibility` 声明式**（部分可观测
> 由规则声明投影，不再依赖 per-game 适配器）。
> 配套工程：`GameEngine` 成为 L2→L3 唯一契约（无 per-game 适配器、
> 无 `interfaces/`）；L1 翻译产物必过 `engine_validator`（schema + L2 冒烟
> `smoke_validate(variants="all")`）；L1 另有 **v5.5 增量补丁协议**
> （`layer1_translator/rule_patch.py`，RFC-6902 风格子集，大模板变体专用）。

## 2. variants 声明式

把「变种 + 人数 + 常量补丁 + 配比」从**逐游戏代码/启动参数**下沉为**规则 JSON
自身的数据声明**。引擎（`layer2_engine/core/engine.py` `_resolve_variants`）
做纯数据解析，**没有任何 constants 注入 API**（不向外部暴露补丁入口）。

### 2.1 结构

```json
{
  "variants": {
    "variant": "guangdong",
    "player_count": 4,
    "options": {
      "guangdong":   { "constants": {} },
      "hongzhong":   { "constants": { "wild_tile": "z5" } },
      "blood":       { "constants": { "tile_ids": ["m1", "...", "z9"] } },
      "sichuan":     { "constants": { "tile_ids": ["m1", "...", "z9"] } },
      "changsha":    { "constants": { "tile_ids": [...], "pair_258": [...], "fan_pay": [...], "gang_actions": [...] } },
      "taiwan":      { "constants": { "win_tiles": 17, "meld_k": 5 } },
      "international": { "constants": { "fan_pay": [1, 2, ..., 88] } }
    },
    "player_ids":   { "type": "map", "over": { "type": "range", "from": 0, "to": "$player_count" }, "as": { "type": "concat", "parts": ["p", { "type": "get", "path": "$node" }] } },
    "deal_target":  { "type": "if", "cond": { "type": "eq", "a": "$variant", "b": "taiwan" }, "then": 16, "else": 14 },
    "trim_players": true,
    "trim_utility": true
  }
}
```

要点：
- **`options` 是 dict，键=变体名**；每个条目内的 `constants` 是**补丁**（
  与基础 constants 合并，同键覆盖）。不存在「列表 + match 键」写法。
- 引擎按名索取：`_resolve_variants` 用 `options[<variant名>]`；未知变体 →
  `ValueError("unknown variant {name!r}; declared options: ...")`（engine.py
  L155-156）。
- `player_ids` / `deal_target` 等是**表达式**，可以用 `$variant` /
  `$player_count` / `$constants` / `$players` 上下文求值（例如
  `map(range(0, $player_count) → "p{$node}")` 生成任意人数的座位名；
  werewolf 的 `player_ids` 引用 `$constants.role_pool` 长度）。
- `trim_players` / `trim_utility`：按声明人数裁剪 players 数组与
  utility 定义（未参与对局的座位不产生效用）。
- 声明式能力是规则的**自描述**：L1 的 `SchemaValidator._validate_variants`
  是第一道闸（options 非空对象、constants 为对象、默认 variant 必须已声明、
  player_count ≥ 1、trim 为布尔、player_ids/deal_target 为表达式对象）。

### 2.2 构造时的解析顺序（engine.py `_resolve_variants`）

1. 无 variants 节（存量 5.0/5.1 文件）→ 不做任何处理，直接用基础 rules。
2. 有 variants 节 → 校验 `variant` 是否在 `options` 声明，否则 ValueError。
3. 取 `options[variant].constants` 补丁合并进基础 constants；并写入
   `constants["variant"]` 与 `constants["player_count"]`。
4. 其余表达式键（`player_ids`/`deal_target` 等）用 `$variant` /
   `$player_count` / `$constants` / `$players` 上下文求值。
5. `trim_players` / `trim_utility` 裁剪。

### 2.3 实例：四个 v5.2 文件

| 文件 | 默认 | 变体 | 配比/人数机制 |
|------|------|------|--------------|
| mahjong.json | guangdong × 4 人 | 7 变种（guangdong/hongzhong/blood/sichuan/changsha/taiwan/international） | 136 张基础（guangdong/hongzhong/taiwan/international）；108 张补丁（blood/sichuan/changsha）；taiwan 16 张手牌；player_ids 公式生成 2/4 人 seat |
| werewolf.json | default × 9 人 | 仅 default | 配比本体在 `constants.role_pool`（wolf×3/villager×3/seer/witch/hunter），由 variants 的 `player_ids` 公式按角色数取座位 |
| undercover.json | fruit_normal × 8 人 | 18 变体（6 主题 × 3 难度） | `role_pool` = 1 卧底 + 1 白板 + (N−2) 平民（公式）；4..12 人由生成器参数声明的范围，JSON 内无边界字段 |
| uno.json | classic × 4 人 | 6 变体（classic/seven_zero/jump_in/stacking/draw_until/strict_wild4） | 2-10 人由 `player_count` 公式覆盖（players p0..p9 全部预置） |

## 3. visibility 声明式（部分可观测）

`visibility` 节声明「每个玩家能看到什么」，引擎 `project_observation`
按它做字段级过滤/投影，**不再需要 per-game 适配器**。

```json
"visibility": {
  "default": "partial",
  "my_role": {
    "when": { "type": "eq", "a": { "type": "get", "path": "$node._index" }, "b": { "type": "call", "name": "player_index", "args": ["$viewer"] } },
    "keep": true
  },
  "dead_roles": {
    "when": { "type": "eq", "a": { "type": "get", "path": "alive[$node._index]" }, "b": 0 },
    "keep": true
  },
  "env": {
    "seerResult": { "when": { "type": "eq", "a": { "type": "get", "path": "roles[$player_index($viewer)]" }, "b": "seer" } }
  }
}
```

要点：
- `default`：`"public"`（完全公开）或 `"partial"`（默认隐藏，只有 keep
  声明放行）。
- 视图级条目：`keep: true` 的 when 条件命中才保留该行（如 werewolf 的
  `my_role` 只对 `_index == $viewer` 的行）。
- `env` 级条目：对 env 字段做 `$viewer` 条件投影（如 `seerResult` 仅
  预言家可见）。
- 现有部分可观测游戏：werewolf（roles/dead_roles）、undercover
  （他人牌身份隐藏；无 `my_role` 完全不可见）、uno（他人手牌隐藏但
  保留张数）、texas_holdem（hiddenWorld + 投影）。

## 4. GameEngine 契约（L2→L3 唯一契约）

```python
engine = GameEngine(rules, seed=None, variant=None, player_count=None, allow_codegen=True)
```

13 个公共方法契约：
`create_initial_state` / `get_node_type` / `get_current_player` /
`get_legal_actions` / `apply_action` / `get_chance_outcomes` /
`apply_chance` / `sample_chance` / `is_terminal` / `get_utility` /
`project_observation` / `get_info_set_key` / `eval_expr`
（另有 `get_observation` = `project_observation` 别名、`load_state`、
`from_json`）。

- `allow_codegen=True`：`RulesCompiler().compile(...)` 生成原生 Python
  闭包，产物与解释器做 probe 探针对比（4 个探针状态，set 语义），
  不一致或编译不支持形状（`UnsupportedShapeError`）→ **整体回退纯解释器**
  （logger warning）。
- `allow_codegen=False`：跳过编译，纯解释器路径（平台自定义游戏一律
  走此路径，见 security-notes）。
- `get_info_set_key`：投影观测按 schema 顺序紧凑序列化 → sha256 64 字符
  哈希（非完整 JSON；旧 Hybrid cfr_table 不兼容，重训才可复用）。
- 冒烟校验：`layer2_engine/core/smoke_validator.py` `smoke_validate(rules,
  seed=42, variants="all")` 对**每个声明变体**构造 GameEngine 并探针
  初始转移（player 无合法动作→warning、chance 无结果→error、异常→
  "Engine smoke validation failed"）；L1 `engine_validator.validate()`
  即 schema + 此冒烟。

## 5. 零 BUILTIN 与 functions alias

- grep `BUILTIN` 在 rules/ **零命中**：v5.1 起外部函数注册表退役，
  `BUILTIN_FUNCTIONS` 不复存在。
- `functions` 节 = 纯函数 alias：`{"<名字>": {"params": [...], "expr": {...}}}`，
  构造时 `expr.set_functions(defs)` 按名双键绑定（名字+全限定路径）；
  alias 体内禁止递归（静态 DFS 环检测 → RecursionError），解释器调用
  深度上限 32（`_MAX_CALL_DEPTH`）。
- 语言原语只从数学操作角度扩充（`choose/range/sort/group/distinct/
  contains/sum/max/min/at/...`），禁止游戏特供原语。
- `text` 参数预制能力：动作参数 `"type": "text"` 不参与合法动作枚举
  （占位 `""`），solver 把文本放进 `ActionInstance.params`，effector
  经 `$text` 读取（`_build_context` 自动平铺 params）——狼人杀/谁是卧底
  的发言动作。

## 6. chance / effectMap / triggers

- `chance` 只保留两种概率形式：`uniform`（均匀，显式列 outcomes）与
  `explicit`（`prob` 数值列表）；v4.1 的 Weighted 已移除。
- 结算型 chance（夜晚/放逐/摸牌）常用 `explicit` 概率 1.0 +
  `effectRef`/`effectMap`（如 werewolf 夜晚 `probs=[1.0]` →
  `effectMap.resolve = do_night_end`）。
- `sample_chance` 按概率和归一化；空表/全零概率 → ValueError。
- `triggers`：受全局上限 `engine._TRIGGER_CYCLE_CAP = 16` 保护（触发器
  链最多 16 轮，超过即中止，防无限循环）。

## 7. v5.5 增量补丁协议（L1 工具链）

v5.2 是**规则语言**；L1 翻译链路还有一层**工具协议 v5.5**（
`layer1_translator/rule_patch.py`）：

- RFC-6902 风格子集：`{"patch": [{"op": "replace|add|remove", "path":
  "constants.board_size", "value": 9}, ...]}`，点号键路径、数字段=数组下标。
- `apply_patch(base, ops)` 深拷贝后按序应用；任何违例（未知 op/路径解析
  失败/越界/缺 value/操作数超 `MAX_PATCH_OPS=64`）抛 `PatchError`，
  **绝不半份应用**。
- 用途：大模板变体（mahjong ≈87k 字符）走增量补丁，而非 LLM 全量改写
  （`variant_translator`: 模板 > 40_000 字符自动选补丁路径；
  `patch_mode` 可强制）。

## 8. 与 v4.1 图模型的差异（摘要）

| 维度 | v4.1（已废弃） | v5.2（现行） |
|------|---------------|-------------|
| 状态存储 | 属性图 StateGraph（Node/Edge/Env/Meta） | 两层状态：ground 数组 + env（无图） |
| 表达式 | NeighborExpr/RefExpr/first/last/in | 纯函数原语（choose/range/sort/group/at/get/...） |
| 效果 | effects 块 + createNode/addEdge/shuffle/draw/log | effectors：setArray/setVar/remove/add/removeFrom/resolve/effectMap |
| 动作 | actorKind + Param min/max/unique | 动作模板 + params（text 预制）+ canonical_key |
| 概率 | Uniform/Weighted/Explicit | uniform / explicit |
| 部分可观测 | visibility 五档 + aggregateAs | `visibility` 声明式（default/drop/env 投影） |
| 求解器契约 | SolverAdapter 9 方法 | `GameEngine` 13 方法（L2→L3 唯一契约） |
| 语言头 | `languageVersion: "4.1.0"` | `meta.version`（5.0.0/5.1.0/5.2/5.2.0 存量混用） |

## 9. 已知实现细节（与文档语义的偏差登记）

- **switch 编译**：`rules_compiler` 对 switch 生成**无 walrus 的首匹配
  if/elif 链**（`:=` 在 comprehension 迭代表达式里是 SyntaxError，曾经的
  switch-in-comprehension 会让整套规则回退纯解释器；现可正常编译）。
- **switch default**：规范语义「default 取首个」；解释器（expr_eval eval）
  与规则编译器（rules_compiler）均取**首个** default；但热路径编译器
  （expr_eval compile）在存在**多个** default 条目时取**最后一个**——
  已知三路径分歧（当前所有规则只使用单个 default，无实际影响；修
  `expr_eval.compile` 只取首个）。
- **concat 的 None 丢弃**：解释器 `_concat_values` 丢弃 None 项；编译路径
  裸 `+` 拼接（None/混合类型 → TypeError），仅靠 probe 不一致回退兜底
  ——编译子集仅保证全列表/全字符串拼接等价。
- **版本号标签**：engine.py/rules_compiler.py 文件头仍写 v5.0、expr_eval.py
  写 v5.1（历史遗留字符串，功能语义已 v5.2/v5.5）。
