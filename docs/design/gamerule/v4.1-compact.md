# 通用游戏规则语言 v4.1 (精简参考)

## 核心原则

> **JSON 存动作模板，不存动作实例；存观察规则，不存信息集；存随机分布，不存完整博弈树。**

规则 JSON 描述的是"如何生成博弈树"，而非博弈树本身。

---

## 分层架构

```
┌──────────────────────────────────┐
│ AI / Solver Layer                │  ← CFR / MCTS / PSRO / PPO
└──────────────────────────────────┘
               ▲
┌──────────────────────────────────┐
│ Rule Runtime / Compiler          │  ← 动作展开 / 条件求值 / 效果执行
└──────────────────────────────────┘
               ▲
┌──────────────────────────────────┐
│ RulesLibrary v4.1                │  ← 声明式规则 (actions / effects / visibility ...)
└──────────────────────────────────┘
               ▲
┌──────────────────────────────────┐
│ StateGraph                       │  ← 运行时状态 (nodes / edges / env)
└──────────────────────────────────┘
```

## 一、状态模型 (StateGraph)

游戏状态被建模为一个**属性图**：节点代表实体，边代表关系。

| 结构 | 字段 | 说明 |
|------|------|------|
| `Node` | `id, type, props` | 实体：玩家、卡牌、棋盘格子等 |
| `Edge` | `from, to, type, props?` | 关系：owns, adjacent, located_in 等 |
| `Env` | `turn, phase, chain, pendingEffects, publicProps` | 回合/阶段/响应链/公共状态 |
| `Meta` | `gameId, version, seed, startTimestamp, currentSeq` | 对局元数据 |

---

## 二、规则库 (RulesLibrary)

| 字段 | 类型 | 说明 |
|------|------|------|
| `actions` | `ActionTemplate[]` | **核心**：动态生成合法动作 |
| `effects` | `Record<string, EffectDef>` | 状态变更操作序列 |
| `phases` | `PhaseDef[]` | 阶段/回合流转 |
| `visibility` | `VisibilityRule[]` | 不完全信息 → 观察投影 |
| `terminal` | `TerminalRule[]` | 终局条件 |
| `utility` | `UtilityRule[]` | 终局收益计算 |
| `chance` | `ChanceTemplate[]` | 随机节点 (概率分布) |
| `triggers` | `Trigger[]` | 事件 → 自动效果 |
| `queries` / `predicates` | 可复用表达式 | 查询/谓词 |
| `functions` | `FunctionDecl[]` | 外部函数声明 |
| `constants` | `Record<string, any>` | 常量表 |

---

## 三、表达式系统 (Expr)

表达式是 JSON AST 而非字符串 DSL，用于查询、条件、计算。

| 类型 | 关键字段 | 说明 |
|------|----------|------|
| `ConstExpr` | `{const: value}` | 字面量 |
| `VarExpr` | `{var: "$actor"}` | 上下文变量：`$state`, `$actor`, `$env`, `$params` 等 |
| `GetExpr` | `{get: [target, path]}` | 字段读取 |
| `OpExpr` | `and/or/not, eq/neq/gt/lt, add/sub/mul/div, in/contains, count/first/last, map/filter/any/all` | 逻辑/算术/集合 |
| `QueryExpr` | `{query: {type?, where?, limit?}}` | 按类型/条件查询节点 |
| `NeighborExpr` | `{neighbors: {from, edgeType?, nodeType?, direction?}}` | 图邻接查询 |
| `CallExpr` | `{call: [fn, ...args]}` | 外部函数调用 |
| `TemplateExpr` | `{template: "place:{x},{y}"}` | 字符串模板 |
| `RefExpr` | `{ref: "predicateName"}` | 引用命名谓词/查询 |
| `IfExpr` | `{if: {cond, then, else}}` | 条件分支 |

---

## 四、动作模板 (ActionTemplate)

系统的核心——**运行时动态生成动作实例**，而非预枚举。

```typescript
interface ActionTemplate {
  id: string;                    // 模板 ID
  type: string;                  // 动作类型
  actorKind: "player"|"system"|"chance";
  actor?: Expr;                  // 行动者表达式
  phases?: string[];             // 可用阶段
  params?: Record<string, ParamDef>;  // 参数定义 (含候选域 domain 和 filter)
  legal?: Expr;                  // 合法性条件
  effectRef: string;             // 关联效果
  canonicalKey?: Expr;           // 规范动作 key
  abstraction?: ActionAbstractionDef; // AI 抽象定义
  selectable?: boolean;
  priority?: number;
}
```

**动作展开顺序**: 检查阶段 → 计算 actor → 计算参数候选域 → 过滤 → 笛卡尔积 → 检查 legal → 生成 ActionInstance → 生成 canonicalKey。

**参数定义** (`ParamDef`)：声明 `domain` (候选域表达式) + `filter` (过滤条件) + `min/max/unique/optional` 约束。

**动作抽象** (`ActionAbstractionDef`)：将具体动作映射到抽象 key（如 `use_card:card_007->p2` → `use_card:slash->enemy`），支持 `mergeEquivalent` 合并同类动作以降低 AI 分支因子。

---

## 五、效果系统 (EffectDef)

效果 = 一组原子操作的顺序执行。

| 操作 | 说明 |
|------|------|
| `set` | 设置字段值 |
| `inc` | 数值增减 |
| `createNode` / `deleteNode` | 创建/删除节点 |
| `addEdge` / `removeEdge` / `moveEdge` | 图关系变更 |
| `emit` | 发出事件 (触发 Trigger) |
| `enqueueEffect` / `callEffect` | 入队/调用效果 |
| `branch` | 条件分支 |
| `forEach` | 循环 |
| `shuffle` / `draw` | 洗牌/抽取 (带随机性) |
| `log` | 写日志 |

## 六、可见性 (Visibility)

从不完全信息状态生成玩家观察——支持 CFR 信息集的关键。

```typescript
interface VisibilityRule {
  id: string;
  match: { nodeType?, edgeType?, expr? };
  fields: Record<string, VisibilityLevel>;    // public|private|ownerOnly|hidden|masked
  default?: VisibilityLevel;
  aggregateAs?: { field, groupBy, op: "count"|"sum"|"list" };  // 隐藏信息的聚合显示
  priority?: number;
}
```

**观察生成**: 克隆公开状态 → 按优先级应用可见性规则 → 隐藏/掩码字段 → 聚合隐藏信息 → 输出 `Observation`。

---

## 七、随机事件 (ChanceTemplate)

```typescript
interface ChanceTemplate {
  id: string;
  params: Record<string, ParamDef>;     // 随机变量的候选域
  probability: UniformProb | WeightedProb | ExplicitProb;
  effectRef: string;
}
```

概率支持均匀分布、加权分布、显式概率三种模式。

---

## 八、终局与收益

- **TerminalRule**: `{id, condition: Expr, priority?}` — 满足任一终局条件时游戏结束。
- **UtilityRule**: `{player: Expr, value: Expr, when?: Expr}` — 为每个玩家计算数值收益 (零和/一般和)。

---

## 九、求解器接口 (SolverAdapter)

规则引擎必须对外暴露以下统一接口：

```typescript
interface SolverAdapter {
  getNodeType(state): "player" | "chance" | "terminal";
  getActingPlayer(state): string | null;
  getLegalActions(state): ActionInstance[];       // 由 ActionTemplate 动态展开
  applyAction(state, action): GameRoot;           // 执行效果 + 触发器
  getChanceOutcomes(state): {action, probability}[];
  getObservation(state, playerId): Observation;   // 可见性投影
  getInfoSetKey(state, playerId): string;         // hash(observation + publicHistory)
  isTerminal(state): boolean;
  getUtility(state, playerId): number;
}
```

**CFR 约束**: canonicalKey 稳定、visibility 完整、chance 概率可计算、terminal/utility 明确、外部函数 solverSafe、动作生成顺序确定。

## 十、示例骨架 (五子棋)

```json
{
  "languageVersion": "4.1.0",
  "actions": [{
    "id": "place_stone",
    "actorKind": "player",
    "actor": {"var": "$env.turn.currentPlayerId"},
    "params": {
      "cell": {
        "type": "node",
        "domain": {"query": {"type": "board_cell"}},
        "filter": {"eq": [{"get": ["$cell", "props.occupant"]}, {"const": null}]}
      }
    },
    "legal": {"const": true},
    "effectRef": "place_stone_effect",
    "canonicalKey": {"template": "place:{cell.props.x},{cell.props.y}"}
  }],
  "effects": {
    "place_stone_effect": {"ops": [
      {"op": "set", "path": "state.nodes.{cell.id}.props.occupant", "value": {"get": ["$actor", "props.color"]}},
      {"op": "callEffect", "effectRef": "check_win"},
      {"op": "callEffect", "effectRef": "switch_turn"}
    ]}
  },
  "terminal": [{
    "id": "five_in_row",
    "condition": {"call": ["line_match", {"var": "$state"}, {"var": "$lastMove"}, {"const": 5}]}
  }],
  "utility": [
    {"player": {"var": "$winner"}, "value": {"const": 1}},
    {"player": {"var": "$loser"}, "value": {"const": -1}}
  ]
}
```
